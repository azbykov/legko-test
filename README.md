# net-speed: замер скорости скачивания

Консольный скрипт на Node.js. Он делает к указанному адресу 10 последовательных
GET-запросов, на каждом дожидается полного ответа и печатает среднее время
запроса, время до первого байта (TTFB), общий объём скачанных данных и скорость
скачивания.

## Требования

- Node.js **18+** (проверено на 24.x)
- Внешних зависимостей нет, `npm install` не нужен

## Запуск

```bash
git clone <repo-url>
cd net-speed
node src/cli.js https://proof.ovh.net/files/10Mb.dat
```

То же самое через npm:

```bash
npm start -- https://proof.ovh.net/files/10Mb.dat
```

### Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `-n, --count <число>` | `10` | количество запросов |
| `-t, --timeout <мс>` | `30000` | таймаут на один запрос |
| `-h, --help` | | справка |

## Единицы измерения

- **Скорость: Мбит/с** (мегабиты в секунду, 1 Мбит = 10⁶ бит). В этих единицах
  указывают скорость провайдеры и speedtest-сервисы, поэтому результат можно
  сравнить напрямую. В скобках дополнительно выводится МБ/с.
- **Объём: МБ** (1 МБ = 10⁶ байт, десятичные единицы). Точное число байт тоже
  выводится.
- **Время: миллисекунды.**

## Как считается

Время одного запроса измеряется от отправки запроса до получения последнего
байта тела (`performance.now()`). Тело читается потоком: байты считаются, но в
памяти не хранятся, так что большие файлы скачиваются без проблем.

Каждый запрос раскладывается на две части:

- **TTFB** — от отправки запроса до первого байта тела (DNS, TCP, TLS, ожидание
  сервера);
- **передача тела** — от первого до последнего байта.

```
среднее время  = Σ время_запроса / N
общий объём    = Σ байт_в_ответе
скорость       = общий объём × 8 / Σ время_запроса   →  Мбит/с  (end-to-end)
скорость тела  = общий объём × 8 / Σ время_передачи  →  Мбит/с  (без TTFB)
```

- **Download speed (end-to-end)** — скорость так, как её видит пользователь, с
  учётом ожидания ответа.
- **Transfer speed (body only)** — скорость без TTFB, она ближе к реальной
  скорости соединения. Если тело пришло одним куском и время передачи слишком мало
  для измерения, выводится `n/a`.

Обе скорости считаются по суммарным байтам и суммарному времени, а не как среднее
скоростей отдельных запросов. Так они корректны, даже если ответы разного размера.

## Особенности и ограничения

- **Кэш.** Запросы уходят с заголовками `Cache-Control: no-cache` и `Pragma: no-cache`.
  Если CDN их игнорирует, часть ответов может отдаваться из кэша.
- **Сжатие.** Отправляется `Accept-Encoding: identity`. Запросы выполняются через
  `node:http`/`node:https`, которые отдают тело как есть, поэтому считаются
  байты, реально полученные по сети. Если сервер всё равно сжал ответ, в строке
  запроса появится пометка `[gzip]`/`[br]`, а в конце — примечание: объём и скорость
  посчитаны по сжатым байтам. (Встроенный `fetch` сам распаковывает ответ и
  завышал бы объём.)
- **Первый запрос** обычно медленнее остальных: на него приходятся DNS, TCP и
  TLS-рукопожатие. Последующие запросы переиспользуют соединение (keep-alive).
  Разница видна по TTFB и по min/max.
- **Маленькие файлы.** На них доминирует TTFB, и end-to-end скорость получается
  заниженной. Смотрите на Transfer speed или берите файл от нескольких мегабайт.
- **Один поток.** Запросы идут по одному соединению, а один TCP-поток не всегда
  загружает весь канал. Скорость показывает загрузку конкретного URL, а не
  максимум вашего интернета.
- **Ошибки.** Невалидный URL, сетевая ошибка, таймаут, ответ не 2xx, зацикленные
  редиректы или пустое тело (0 байт) прерывают прогон: среднее по неполному набору
  вводило бы в заблуждение. Коды выхода: `0` — успех, `1` — ошибка запроса,
  `2` — неверные аргументы.
- **Таймаут** (`-t`) действует на весь запрос целиком: редиректы и чтение тела.
- **Редиректы** обрабатываются автоматически (до 10, в том числе между http и https).

## Структура

```
src/
  cli.js        разбор аргументов, вывод, коды выхода
  benchmark.js  N последовательных запросов и агрегация
  measure.js    один запрос (node:http/https): время, TTFB, подсчёт байт
  utils.js      форматирование, перевод в единицы, разбор аргументов
test/           тесты на node:test с локальным HTTP-сервером
```

## Тесты

```bash
npm test
```

Тесты поднимают локальный HTTP-сервер и проверяют подсчёт байт (в том числе
сжатых), TTFB, ровно N запросов, заголовки, редиректы, пустое тело, обработку
404 и таймаута, а также CLI целиком.
